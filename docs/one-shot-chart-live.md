# 一键演出

MFA 的 **▶️ 一键演出** 默认不勾选，用 MFA 已连接的控制器等待最终开场封面、按本地 SUS 演奏一曲，然后结束任务。基准环境为日服 MuMu、横屏 1280×720、240 DPI。

## 使用方式

1. 在游戏中手动进入单人或协力，选择歌曲及难度。
2. 在「一键演出」任务中选择相同的 EASY、NORMAL、HARD、EXPERT、MASTER 或 APPEND。任务默认 EASY，必须与游戏中已经选择的难度一致。
3. 在 **MFA 设置 → 演奏设置** 选择演奏引擎及手动偏移。Native 需关闭「自动使用校准配置」，因为这个入口不确认单人或协力模式，不能复用未验收的模式校准。
4. 启动任务，并手动完成游戏中的开始／准备操作。任务持续等待最终封面，最长五分钟；识别成功后自动演奏，完整输入并确认生命栏消失或 LIVE CLEAR 后停止，留在当前完成页面。

任务只提供难度选项，不选曲、不匹配房间、不点击准备、不推进结算，不调整体力或使用饮料。游戏中的体力消耗由手动准备过程决定。「演奏设置」中的引擎和手动偏移会用于演奏，其体力设置不会在此入口执行。

## 身份与首音

仅使用开场最终封面的固定封面区域与标题区域确认歌曲。两者各自提供独立判断机会，明确身份冲突时拒绝输入；不把准备页、成员房间、投票、加载或结算页作为入口。难度由任务设置提供，不读取游戏难度条；难度不一致会导致使用错误的触控计划，使用前必须自行核对。

识别后只加载本地已校验的对应难度 SUS，不在游戏准备期间下载谱面。识别到五分钟截止前的封面后，首音同步仍有独立的等待窗口；沿用共用同步版本 6、触控计划版本 4 及现有样本、拟合与启动余量门槛，不从中途开始或降低门槛。等待期间已处于演奏页面不会触发补打，仍等待新的最终封面。

## 完成、失败与停止

- 五分钟未识别到最终封面时结束任务并保存失败原因；不发送谱面输入或页面点击。
- 识别成功但本地谱面缺失、路径／哈希异常、首音同步失败，或演奏失败时，先确认触点释放，再发送一次 Android HOME，确认模拟器 Launcher 焦点后结束任务。
- 生命值连续两帧确认零，或游戏显示 LIVE FAILED 时，同样先释放再返回模拟器主页。
- 演奏中由暂停按钮与固定 LIFE 标签共同确认页面，单帧模板漏识别先等待；两张有效画面都缺失才中断，纯黑／纯白帧不计入缺失次数。生命零继续独立确认。
- 用户停止时中止并释放，不追加 HOME 或页面输入。释放未确认时保留失败证据并停止页面操作。
- 完整派发、Native 执行回执、本轮 reset 与设备进程清理确认后，再等待结束，最长 120 秒。本局见到的固定 LIFE 标签在两张有效画面中连续消失即可确认，纯黑／纯白转场先等待；生命零仍有标签，继续沿用零生命保护。LIVE CLEAR 是辅助证据，漏识别不会成为停止错误。只有实际命中该文字才记录 `cleared`，生命栏消失则记录 `ended` 与 `end_detection`。任务不读取结算判定数字，不把输入结束当作完整成绩。

报告写入部署目录 `debug/one-shot-chart-runs/`，包括身份、任务难度来源、同步、输入／释放、结束状态及截图，另有汇总 `results.csv`。`result_status` 为 `not_collected`，不产生 PGGBM 或准确率；报告落盘失败不会确认完成。

## 验证范围

2026-10-04 完整 Python 回归 230 项通过。其中新增入口的定向测试核对了任务配置隔离、五分钟虚拟时钟等待、超时零输入、缺谱与资源异常、Native 停止和释放、生命零 HOME、结束后零结算操作及持久化失败。

23 张保存帧回放覆盖 21 张协力截图及单人准备／最终封面：三个最终封面可确认歌曲 520、774、186，其余页面均未触发入口。此证据验证识别范围；一键演出在实际单人、协力中的完整一曲及实际五分钟等待尚未实机验收，不复用已有单人循环任务的验收结论。

结束判断修正通过完整 Python 回归及保存帧回放：关闭 LIVE CLEAR / LIVE FAILED 识别后，实际黑屏转场不会误停，生命栏仍在的结束动画继续等待，结算画面两帧确认后退出等待，未发送结算点击或 BACK。连续性修改仍待实机验收。
