# 演奏轻量 trace

协力游戏判定反馈开启时，`trace.jsonl` 保存各次 FAST／LATE／GREAT／PERFECT 匹配分数、combo 字形签名、投票证据和请求修正；播放器另外记录各窗口实际生效的修正及首动作，区分请求与已发布相位。释放确认后新增 `native-touch-receipts.jsonl`，逐动作关联原目标、修正目标、实际 commit barrier 时间及真实执行延迟，全部相对冻结 epoch。修正后延迟以实际目标计算，原计划延迟同时保留。未开启反馈时不收集这份逐动作扩展，不追加设备输入或观察。

单人、协力和一键谱面演出默认保存轻量诊断，不启动录像。实现参考 MaaBanGDream 的
`agent/realtime/profile_play_action.py` 中 `video_enabled=False` 分支，以及
`agent/realtime/debug_recorder.py` 的时间、触控、生命、结果和丢弃计数约定。
PJSK 按本地谱面派发，保护观察频率远低于实时音符检测，因此观察阶段只把少量数值追加到内存；
序列化、文件创建和写盘全部放在播放器输入结束及释放清理之后。

## 文件与时间

每局 `report.json` 的 `performance_trace` 指向最新记录，`performance_traces` 保留各次尝试。
协力文件位于本次 `attempt-N/` 内；单人和一键文件位于本局目录。

- `trace.jsonl`：首行 `session` 保存歌曲、谱面哈希、首音锚点、冻结偏移和算法版本；
  中间 `observation` 保存谱面相对时间、生命条颜色像素数、零生命确认、页面分数、
  派发／执行进度及当时的命令成本补偿；末行 `outcome` 保存完成、失败、取消、释放和实际结算。
- `touch-plan.jsonl`：按原顺序保存整张已编译触控计划，含动作编号、谱面时间、触点和坐标。
  Legacy 复用播放器已经收集的逐动作延迟，并区分尝试派发与控制器成功回执。
- `native-jlog.jsonl`：沿用已有逐命令设备执行记录；trace 头部保存设备时钟偏移、
  歌曲起点和触控表面旋转，便于关联同一时段的计划与实际命令。

Native 回执的设备毫秒时间除以 1000，加 `device_clock_offset_s`，再减
`playback_epoch_s`，得到本局相对秒数。计划目标为 `Touch.time + timing_offset_ms / 1000`。
设备派发／执行延迟不等于游戏 FAST／LATE；游戏五类判定只使用实际结算读数。

## 派发与证据边界

记录不连接控制器、不增加截图、OCR 或保护检查，不修改触控计划、队列窗口、歌曲相位和偏移。
协力沿用最多两秒一次检查及 Native 余量门槛；单人和一键沿用各自原有观察机会。
Legacy 连续输入期间没有安全空档时不会为了 trace 插入观察。

生命条颜色像素数用于定位变化，不能当作精确 LIFE 数字。已有空条与实读零证据成立时才保存
`life.value=0`，其他数字为 `null`；未知页面的条带数据也为 `null`，不重复上一帧读数。
低频记录不能还原每个音符的游戏判定，已有中段截图缺失的旧局不能事后补造。

trace 不受生命小图最近 240 组缓存限制，覆盖本局所有实际观察机会。为限制异常长任务的内存，
最多保留 16384 条观察；超出时记录丢弃数并标为 `truncated`，不停止演奏。
记录或写盘失败只标记 `performance_trace.status=failed`，不改变任务完成计数或成功／失败状态。
重匹配和下一局重新创建记录，失败及用户停止仍保存已经收集的部分证据。

自动测试覆盖超过八分钟的记录、两次归零异常、未知页面、记录失败、不同尝试隔离，
以及整曲 Native 开关 trace 后命令完全相同、全部执行与零断粮。
这些验证属于离线证据；真实设备上的额外耗时须结合后续用户局的 `playback.observation` 继续核对。
