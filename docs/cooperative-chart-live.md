# 协力谱面演出

MFA 任务列表中的 **🤝 协力谱面演出** 默认不勾选，通过 MFA 已连接的日服 MuMu 控制器按本地 SUS 演奏。基准环境为横屏 1280×720、240 DPI；首版覆盖截图所示的自由、资深公房，不需要房间号。每局结算回到游戏主页，再重新匹配公房。

## 任务选项

开场失败报告的 `anchor_attempt` 保存实际样本、数量及状态，单个候选超时记为 `candidate_motion_unconfirmed`，多点轨迹超时记为 `trajectory_gate_timeout`。
候选尚未确认运动时不能据此断言第一音已经通过，也不能从后续音符启动。候选被静止或倒退观察替换后，报告跟随实际值。
截图证据保留基线、最近 31 帧、首个采纳样本和最新 32 个采纳样本来源帧，去重按拍摄时间排序，最多 65 张；复用已有截图，成功时仍在释放后保存，不在开场临界区编码。
原诊断改动保持超时、拟合及启动余量不变；2026-10-06 的候选修复已同步版本 8，离线证据完整性不代表协力首音失败已治愈。
2026-10-05 17:51 经用户授权仅做 548「ぼくのかみさま」EXPERT 单人对照：0 体力、不用药、Native 手动 −51 ms，792 音全 PERFECT、FAST／LATE 均零，3736 动作全部执行，零断粮，本轮释放与返回主页均确认。首音六样本、最近五点透视拟合残差约 2.34846 像素，保存帧中包含首样本来源帧。此局未复现协力故障且未进入公房，协力根因仍未知，不构成协力修复验收；完整单人证据见 [单人验收记录](solo-chart-live.md#本机验收记录)。

| 选项 | 含义 |
| --- | --- |
| 公房类型 | 自由房间或资深房间，默认自由；资深房间的入场条件由游戏检查，不自动降级。 |
| 选曲方式 | 当前歌曲点击「决定」提交；随机点击「おまかせ」。最终歌曲由房间抽选决定，可能与提交的当前歌曲不同。 |
| 谱面难度 | EASY、NORMAL、HARD、EXPERT、MASTER，默认 EASY；截图只有这五种难度，暂不提供未经页面验证的 APPEND。 |
| 演出次数 | 1–999，默认 1；完整输入、释放及返回主页后推进演出次数；完整个人成绩另计，不因漏读补演。 |
| 体力不足时使用道具 | 关闭、小饮料或大饮料，默认关闭。 |
| 每次回复饮料数量 | 1–99，默认 1；每次不足按指定瓶数回复，不自行追加或降低消耗。 |

引擎、手动触控偏移和每局体力消耗沿用 **MFA 设置 → 演奏设置**。每次任务首次匹配前两帧确认并保存一次消耗设置，成功后后续局及普通恢复、新报告沿用本任务快照；`bonus.confirmation_source=task_snapshot` 和 `source_report` 明确记录首次确认来源，不伪造本局检测。每次匹配前仍两帧确认实际可用体力，不足时按指定种类与瓶数同页批量回复。游戏消耗仍由用户选择：沿用当前设置或指定 0–10；0 消耗不读取体力、不用药。匹配后不操作体力回复，避免占用其他玩家的准备时间。

每批在同一回复页复位两个滑条，按设置 N 瓶点击所选药加号 N 次，一次决定、一次 OK，不逐瓶返回重进。实际体力须连续两帧一致且达到本批预期增量（小药 +N、大药 +10N）才确认到账；只增加 1 不能证明 N 瓶已用，不以像素差判断。用药前读数异常不使用饮料，整批到账后先持久化已用瓶数，再关闭完成提示；确认请求失败、服务器延迟或关闭失败保留证据，不重新执行整批。普通恢复后的实际体力已够开演，也仍保留原已请求 OK、尚未足额确认的批次，不将其改记为完整到账。

本机已独立验收同页五瓶小药：加号五次、一次决定、一次 OK，体力 5→10，两帧到账一致，五瓶进度先持久化再一次 BACK 关闭通知，并确认回主页。此次在单人准备页执行共用 Navigator，没有开演；沿用协力已保存的小药五瓶设置作为输入，演奏设置及各任务种类／瓶数保持不变。大药多瓶、AUTO 与协力任务实际触发仍须独立验证，未新增协力演出。

Native 使用现有设备队列与当前手动偏移。首版协力没有独立实机验证的校准配置；若全局开启「自动使用校准配置」，任务会提示先关闭此选项，并在设备操作前停止。不会把单人校准结果当作协力校准，也不修改用户保存的校准开关、流速或游戏判定偏移。

## 页面流程与身份

用户编号截图确认的流程为：主页 → 演出菜单 → 公房选择（2）→ 匹配（3）→ 提交歌曲（4）→ 等待选曲／随机抽选（5）→ 难度选择和准备（6）→ 加载／过渡（7）→ 可选的队友加载等待（8）→ 最终封面（9）→ 演奏（10）→ 结算（11–13）。匹配、抽选、加载和队友等待均不发送点击。

难度选择页对倾斜封面做透视校正，同时判断本地封面与日文标题；通过本机难度圆钮的实心颜色确认选中状态，不读取其他玩家卡片作为本机难度。准备页保留两帧观察，身份稳定时提前校验本地 SUS 并准备 Native；身份未确认时仍可在实际难度确认后提交准备，继续等待开场页。准备按钮消失后不重复点击，以免落在取消按钮上。

准备页与开场页各有封面、标题两种判断机会，共四种机会。整图分数不足时，封面可用带空间覆盖约束的特征配准确认，避免评级标记遮挡导致误拒绝；标题先去除封面底边和背景，独立确认要求 OCR 置信度至少 0.85、标题相似度至少 0.90，且与次选相差至少 0.08。任一通道明确且唯一即可提供身份，两个明确通道冲突则拒绝使用；已确认的准备页身份仍须与开场页一致。开场页必须确认实际难度条，准备页未确认时在此处加载并校验 SUS、生成触控计划和初始化 Native；这些步骤来不及完成首音同步时拒绝本次启动，释放后等待安全页面恢复。

所有加载等待都保持零谱面输入。共用同步版本 9 在原几何通过后要求候选亮芯、小幅倒退不采纳为轨迹，并保留金色外框、长条起点及透视模型的判断；快截图的最后五帧不足 250 ms 时，若已有至少八点及 250 ms 的运动轨迹，就使用最近不超过 1.25 秒、最多 32 点拟合，避免局部斜率抖动放大成整曲提前。不为凑样本多等待一帧，宽拟合不合格也不退回短尾；慢链路两／三／四帧、残差、启动余量与拒绝中途启动门槛不变。共用触控计划版本 4 区分长条判定点与路径节点，避免占位坐标切断实际曲线。报告 `identity_checks` 分别保存两个阶段的封面及标题证据，每个阶段最多保留 24 次观察。版本 9 新修复及尚未覆盖的同步路径仍须用户实机验收，既有版本 7 正常多局记录保留历史范围。

演奏设置新增默认关闭的「协力演奏中按 FAST / LATE 微调（试验）」，仅 Native 协力生效。复用现有两秒保护截图，在同帧确认 GREAT 和 FAST／LATE 字形；12 秒内三个有效同向证据、且 combo 改变，才延后／提前尚未发布的输入 5 ms。每次至少间隔六秒，累计限制 ±60 ms，基准 epoch 和手动偏移不变，已经发布的队列不撤回。普通文字短暂消失不投票，可信 PERFECT、反向／冲突、生命 HUD 未知、相同 combo 或采样中断会清空旧证据。只记录内存数值，释放后写轻量 trace 及逐动作真实目标；命令耗时回执不参与游戏方向判断。缺模板、非 Native 或识别出错时记录状态并沿用原相位，演出继续。

本机判定模板由 `scripts/build-game-timing-templates.py` 从人工确认过的 FAST+GREAT、LATE+GREAT、LATE+PERFECT 参考图生成，只保留文字二值字形，写入 `.local/game-timing-templates/`；部署脚本复制到运行包。没有这些模板的机器保持关闭或退回原相位，不自行接管设备采样。

房间解散提示在成员匹配、准备及加载阶段用于恢复。原有带 `(105)` 的横幅出现在用户标注的编号 4–7：选歌、抽选、难度准备及加载等待均检查。用户确认横幅点击和 ESC／Android BACK 均可关闭：日志与证据写入后重新取帧确认文字，第一次请求点击原横幅中心 `(640, 360)`，同一横幅持续时第 2／3 次请求才使用 BACK。总请求最多三次、间隔至少一秒，仍受 20 秒恢复期限限制；一次有效后停止请求，不点新位置，BACK 不用于其他页面。`notice_click_count` 只计点击，`notice_back_count` 计 BACK，`notice_dismiss_request_count` 及 `notice_dismiss_requests` 保存总数和各次方法。确认无横幅的实际房间选择页才记 `notice_dismissed=true`，黑白转场或单帧负匹配不证明关闭，横幅再次明确出现仍保留剩余重试；控制器输入回执成功不能冒充关闭证明。实际返回编号 2 才重匹配，最多三次，恢复不计入完成次数。

成员满员后退出还可能出现「ルームが解散されました。」确认弹窗，任务在日志和证据编码后重新取帧，同时确认文字及 OK，仍点击一次后等待实际房间选择页。横幅或弹窗消失、黑白转场时不输入底层页面，已进入演奏或用户停止时拒绝关闭或重匹配；新帧已转最终封面时不继续横幅点击或 BACK，也不绕过原封面、标题和实际难度门禁。有限横幅恢复与转场保护已通过离线流程回归，实际关闭效果仍待实机验收。

成员房间等待选歌的无进展上限为 180 秒，加入请求前记录期限，连接异常或恢复不重新计时。截止时重新取帧：选歌已出现就继续原房间，仍显示 MATCHING 才进入最多 20 秒的恢复等待。按 2026-10-06 用户进一步确认，房内超时统一使用 ESC／Android BACK，不再点击返回箭头或取消按钮。只有新帧唯一正向确认 MATCHING、选歌、MUSIC SHUFFLE 抽选、准备或已准备页，且无暂停与 LIFE、零谱面输入及当前释放证明成立，才允许发送。灰箭头不限制 ESC；黑白、未知、加载、最终封面或演奏页不退出。日志和写帧后再次截图复核，请求先计数，最多三次、仍受同尝试 20 秒恢复期限限制。退出期间正向进入下阶段就接续原房间，不重复入房、投票或准备。

只有实际返回自由／资深房间选择页后才重新匹配。恢复与解散共用每个待完成演出最多三次重匹配，只有实际安全返回房间选择、主页或菜单并准备新入房才消费一次，普通失败不预扣，不增加演出完成次数，也不改变体力消耗或回复设置。进入演奏、页面不明、已有谱面输入或触点未释放时不退房；恢复截止仍未确认房间选择页或选歌页则保存失败，转为可取消的安全页面等待。

重匹配前清理已经准备的 Native 进程并取得释放回执；已派发谱面输入后不重匹配或重放。每次页面输入前重新取帧确认，等待支持用户停止。模板裁剪清单包含成员房间满员后解散的确认弹窗、未满员的等待房间及两处独立队伍结算文字，十二个协力模板仍必需；新增成员决定模板可选，缺少时保持旧 WAITING 路径。

## 普通故障恢复、生命零与停止

2026-10-05 按用户「除演出中死亡外尽量不要停止」的新要求，普通运行故障保存原失败后保持同一待完成演出。此前缺谱、输入异常或导航超时一律 HOME 并终止的规则已被本节替代；参数、环境及校准配置验证门禁不绕过。

- 主页 → 演出菜单 → 房间选择共用 60 秒期限，HOME 与多人按钮各最多三次请求，均须新帧确认原页且无暂停及 LIFE。请求先计数，回执失败也消耗预算；普通恢复不重置期限或次数。已在房间选择页可直接接续，期限／预算耗尽则保持可取消等待，不盲按 BACK。
- 身份未确认、缺谱、首音门槛未通过、解散上限、结算或输入异常均不增加演出次数。已输入的失败尝试不复用旧播放器、epoch 或队列；正常恢复须重新确认身份、难度、本地谱面与首音。
- 当前 Native 对象一直保留到本轮 reset 回执和设备进程清理成立。释放未知时只等待清理；连接恢复、HOME 截图或新进程都不是释放证明，不发送页面输入或创建新播放器。
- 释放后仅在无暂停及固定 LIFE 标签的明确游戏主页、演出菜单或房间选择页恢复准备，并重新验证连接、尺寸、DPI 与前台。演奏 HUD、最终封面、加载、标题、黑白或未知页面只低频等待，可随时停止。不会因旧失败自动 HOME 离开正在推进的公房歌曲。
- 恢复中的结算 BACK 要求两张正常间隔的新帧确认同一明确结算页，暂停和 LIFE 均缺失；队伍页需 LIVE RESULT 和全体分数同时达到 0.90，个人页也须达到 0.90。最多三次请求，回执失败也消耗预算。
- 每个待完成演出的重匹配上限仍为三次，普通恢复不重置；耗尽进入等待房间状态。一批饮料不足或已开始的回复结果尚未确认时保留已到账瓶数，等待用户处理，不自动追加另一批。
- 保护采样仍最多每两秒一次。实际死亡须 LIFE 标签、协力条带区域为空及完整数字零连续两次确认，或连续两次正常采样正向确认 LIVE FAILED；单帧误匹配、暂停或 LIFE 缺失均不算死亡。数字零模板至少 0.90，不以 10／100／1000 的末位零代替。
- 真正死亡保留原原因，先取得当前释放证明，再发送一次 Android HOME，确认 Launcher 后终止整批且不计数。清理或连接暂时失败继续可取消等待；用户停止优先，仅中止并释放，不追加 HOME。
- 可见状态说明等待触点释放、连接、安全页面或结果文件可写；状态未变不刷屏。失败 JSON／CSV 每个 run 只保存一条，文件暂时不可写则等待重试，成功落盘后才推进计数。保持等待表示任务仍在运行，不伪装完成或整批失败。

上述恢复只通过离线控制流回归，尚未完成新的协力实机验收。原开场同步、身份匹配及 Native 输入算法不变。

## 个人成绩与计数

编号 11 是队伍总分，编号 12 是各成员成绩概览；只有编号 13 的个人判定面板用于 PGGBM。个人页还需再次匹配本局歌曲、标题与难度，避免把其他局或其他歌曲的成绩保存为本局成绩。

协力只在全部输入派发、全部 Native 设备执行回执、本轮 reset 执行和进程清理均确认后进入结束判断。暂停及 LIFE 不在时，还需连续两帧确认同一明确结算页：队伍结算同时匹配 `LIVE RESULT` 与 `全体スコア` 两处独立文字，个人判定页、实际 LIVE CLEAR 或游戏主页也提供正向页面证据；单纯 HUD 缺失仍等待，不发送 BACK。结束确证后沿用原结算推进，后续奖励动画不用识别新增按钮；演奏 HUD 再出现则再次阻止结算操作。纯黑／纯白先等待。报告使用 `end_detection.method=cooperative_settlement_confirmed`，缺少 LIVE CLEAR 时记 `live_status=ended`，实际命中才记录 `cleared`。

PERFECT、GREAT、GOOD、BAD、MISS 连续两帧相同才接受，并核对本地谱面音数。分数、COMBO、FAST、LATE、FLICK 等可选数字须两帧一致，否则保存为空。判定不完整或音数不匹配时，可取得的实际数字保留在 JSON 和 CSV，记录 `settlement_warning`；返回主页后继续下一曲，不额外补演，也不增加完整记录计数。输入或释放不完整转上述恢复等待，不能伪装成正常结束。

正常结算沿用加速点击后重新取帧、Android BACK 推进，以实际游戏主页为终点，不新增奖励按钮识别。个人判定最多等待 8 秒；仍不完整则保存部分数据并继续结算。结算及返回主页单次最多等待 180 秒，超时保存原失败后进入安全恢复等待。报告位于部署目录 `debug/cooperative-chart-runs/`，包括本局 `report.json`、各尝试的截图／Native 回执及汇总 `results.csv`。`performance_completed` 表示已完成输入及返回流程，`completed` 还要求完整判定及音数核对；JSON、CSV 与释放证据先落盘，再增加完整记录进度。

历史实机记录中的「停止／HOME」描述保留当时行为；当前普通故障策略以本节为准，不据此宣称历史故障已实机治愈。

## 本机模板与部署
